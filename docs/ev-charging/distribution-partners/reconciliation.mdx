# Reconciliation

Sessions and CDRs are the two artefacts you reconcile against. Sessions are
live + mutable; CDRs are immutable + final.

## Pull sessions (live monitoring)

Poll this every 30–60 seconds while your drivers are charging to drive in-app
status (kWh delivered, time elapsed). Run it once daily as a reconciliation
safety net to catch any session updates your real-time poll might have missed.

```http
GET /ocpi/2.2.1/emsp/sessions?date_from=2026-04-29T00:00:00Z&limit=100
Authorization: Token TOKEN_C
X-Request-ID: c0a3d9e5-8094-4d6f-d1a2-6d1f4a7f8f95
X-Correlation-ID: c0a3d9e5-8094-4d6f-d1a2-6d1f4a7f8f95
```

**Response** — `HTTP 200`:

```json
{
  "status_code": 1000,
  "data": [
    {
      "id":              "S1234",
      "country_code":    "MX",
      "party_id":        "CPX",
      "start_date_time": "2026-04-29T10:15:00Z",
      "kwh":             12.4,
      "cdr_token":       { /* token object */ },
      "auth_method":     "AUTH_REQUEST",
      "location_id":     "LOC001",
      "evse_uid":        "LOC001-EVSE-1",
      "connector_id":    "1",
      "currency":        "MXN",
      "status":          "ACTIVE",
      "last_updated":    "2026-04-29T10:33:00Z"
    }
  ],
  "timestamp": "2026-04-29T10:33:01Z"
}
```

`X-Total-Count` header tells you the total available.

## Pull CDRs (final billing records)

CDRs are the final, immutable billing records — one per completed session.
Use them to invoice your drivers and reconcile against the financial
settlements the hub posts back via the `session.settled` webhook.

```http
GET /ocpi/2.2.1/emsp/cdrs?date_from=2026-04-29T00:00:00Z&limit=100
Authorization: Token TOKEN_C
X-Request-ID: d1b4e0f6-91a5-4e80-e2b3-7e2a5b80909a
X-Correlation-ID: d1b4e0f6-91a5-4e80-e2b3-7e2a5b80909a
```

Or fetch a single CDR by ID:

```http
GET /ocpi/2.2.1/emsp/cdrs/MX/CPX/CDR-S1234
```

## Recommended reconciliation pattern

1. **Real-time**: subscribe to the [`session.settled` webhook](/webhooks/events) — every settled session POSTs the cleared amounts to you the moment they're finalised
2. **Daily batch**: pull `/emsp/cdrs?date_from=<24h ago>` and reconcile against your books — catches any webhook deliveries that failed
3. **Weekly safety net**: pull `/emsp/cdrs?date_from=<7 days ago>` with no time bound, compare counts against your local store. Any drift triggers a re-import of just the missing IDs
