# Sandbox

## URL

The sandbox runs at the same URL as production with sandbox-specific
credentials issued separately. Contact [partner@networkcore.org](mailto:partner@networkcore.org)
during onboarding to receive your sandbox Token A.

## Demo seed

The demo seed populates the sandbox with realistic data. Ops triggers
the seed for you on request — typically right after your sandbox
credentials are issued.

| Item | Count |
|---|---|
| Parties | 5 (3 CPOs, 2 DPs) |
| Locations | 12 |
| Sessions | 150 |
| CDRs | ~95 |
| Cleared records | ~80 |
| Settlement batches | ~25 |
| Invoices | ~240 (3 per cleared session) |
| Chargebacks | 9 across every lifecycle status |
| Risk fingerprints | 60 (including farming + compromised clusters) |
| Risk signals | 30 across LOW/MEDIUM/HIGH/BLOCK |
| Fraud flags | 6 across scopes + severities |
| BIN intelligence | 5 across all four tiers |
| First-loss envelopes | 2 (one per CPO) |
| Distributions | 3 (for LOST chargebacks) |

## What's NOT in sandbox

- Real bank wires — payouts return mock "submitted" responses
- Real CFDI stamping — FacturAPI returns canned UUIDs + placeholder PDFs
- Real wallet movements — SDK.finance returns canned balances

Everything else (auth, OCPI validation, rate limits, idempotency, webhooks)
behaves identically to production.

## Reset

Ops can wipe + re-seed the sandbox on demand. If your test data has drifted
into a weird state, ask us to reset — takes &lt;1 minute.
