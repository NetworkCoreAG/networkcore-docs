# Pagination

List endpoints accept:

- **`limit`** — default 50, max varies per endpoint (typically 100 or 1000)
- **`offset`** — default 0

```http
GET /portal/v1/cpo/sessions?limit=50&offset=0
GET /portal/v1/cpo/sessions?limit=50&offset=50
GET /portal/v1/cpo/sessions?limit=50&offset=100
```

## Determining when you're done

Responses include an `X-Total-Count` response header where computing it
isn't prohibitive:

```http
HTTP/1.1 200 OK
X-Total-Count: 247
```

Stop when `data.length < limit`. The `X-Total-Count` upfront tells you how
many pages you'll need.

## OCPI pagination

OCPI list endpoints (`/emsp/locations`, `/emsp/sessions`, `/emsp/cdrs`)
also accept `date_from` + `date_to` filters. The hub returns a `Link:`
header with `next` / `prev` rels per OCPI 2.2.1 §4.4:

```http
Link: <.../emsp/locations?limit=100&offset=100>; rel="next",
      <.../emsp/locations?limit=100&offset=0>; rel="prev"
```

Following the `next` link is the canonical OCPI pagination pattern — use
that rather than manually computing offsets.
